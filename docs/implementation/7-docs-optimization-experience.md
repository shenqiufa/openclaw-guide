# 7 個文檔優化經驗

> 記錄 2026-04-05 優化 7 個核心文檔的完整過程和經驗

**版本**: v4.7.2

## 🎯 優化目標

解決兩個普遍問題：
1. **存放的內容不符合定義** - 文檔內容偏離官方定義
2. **同一個東西存放到多個文檔裡面** - 內容重複

---

## 📊 優化前狀況

### 問題 1：內容不符合定義

| 文檔 | 問題描述 |
|------|---------|
| **TOOLS.md** | 包含配置 + 規範 + 工作流程（應該只有配置） |
| **SOUL.md** | 包含身份 + 溝通規範（應該只有身份） |

### 問題 2：內容重複

| 重複內容 | 出現在 | 應該在 |
|---------|--------|--------|

| 時間詞彙轉換 | TOOLS.md + AGENTS.md | AGENTS.md |
| 記憶系統 | MEMORY.md + AGENTS.md + HEARTBEAT.md | 分工明確 |

### 步驟 1：確認內容邊界

**參考文檔**：`GROWTH-PLAN/docs/architecture/7-docs-architecture.md`

**內容邊界表**：
```markdown
| 內容類型 | 應該在 | 不應該在 |
|---------|--------|---------|
| 價值觀 | SOUL.md | AGENTS.md、MEMORY.md |
| 個性風格 | IDENTITY.md | SOUL.md、AGENTS.md |
| 用戶信息 | USER.md | MEMORY.md、SOUL.md |
| 行為規範 | AGENTS.md | SOUL.md、MEMORY.md |
| 工作流程 | AGENTS.md | SOUL.md、HEARTBEAT.md |
| 工具配置 | TOOLS.md | AGENTS.md、MEMORY.md |
| 用戶偏好 | MEMORY.md | USER.md、TOOLS.md |
| 關鍵教訓 | MEMORY.md | AGENTS.md、SOUL.md |
```

**使用方法**：
1. 打開內容邊界表
2. 對於每個文檔中的每個章節，問："這個內容類型應該在哪個文檔？"
3. 如果不應該在當前文檔，移動到正確位置
4. 如果重複出現在多個文檔，只保留一處

## 💡 核心經驗

### 經驗 1：先理解官方定義

**每個文檔都有明確的官方定義**：
- SOUL.md = 身份定義（"你是誰？"）
- AGENTS.md = 行為規範 + 工作流程（"你如何做？"）
- TOOLS.md = 本地配置（"你用什麼工具？"）
- MEMORY.md = 長期記憶（"你記住了什麼？"）
- HEARTBEAT.md = 心跳配置（"你主動做什麼？"）

**優化前先問**：
- 這個文檔的官方定義是什麼？
- 當前內容是否符合定義？
- 不符合的內容應該去哪裡？

---

### 經驗 2：使用內容邊界表

**內容邊界表是優化的核心工具**：
```markdown
| 內容類型 | 應該在 | 不應該在 |
|---------|--------|---------|
| 價值觀 | SOUL.md | AGENTS.md、MEMORY.md |
| 行為規範 | AGENTS.md | SOUL.md、MEMORY.md |
| 工具配置 | TOOLS.md | AGENTS.md、MEMORY.md |
```

**使用方法**：
1. 對於每個章節，判斷"這是什麼內容類型？"
2. 查表確認"應該在哪個文檔？"
3. 如果不在正確位置，移動它
4. 如果重複出現，只保留一處

---

### 經驗 3：區分"配置"和"規範"

**配置（Configuration）**：
- 是什麼（What）
- 具體的值
- 例如：飛書 appId、SSH 主機、TTS 語音

**規範（Guideline）**：
- 如何做（How）
- 行為規則
- 例如：搜索工具優先級、飛書消息格式

**區分方法**：
- 如果是一個"值"，是配置 → TOOLS.md
- 如果是一個"規則"，是規範 → AGENTS.md

---

### 經驗 4：區分"記憶"和"規範"

**記憶（Memory）**：
- 具體的經驗
- 用戶的偏好
- 項目的背景
- 例如："發哥喜歡直接簡潔的回答"

**規範（Guideline）**：
- 通用的規則
- 適用的原則
- 例如："回复應該先結論後理由"

**區分方法**：
- 如果是"發哥喜歡 X"，是記憶 → MEMORY.md
- 如果是"應該做 X"，是規範 → AGENTS.md

---

### 經驗 5：定期審查

**優化不是一次性的，需要定期審查**：

**建議頻率**：每月 1 次

**審查清單**：

- [ ] 檢查文檔大小是否合理

**自動化建議**：

- 每月 1 日自動執行
- 生成審查報告
