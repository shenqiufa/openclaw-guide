# 7 個核心文件掃描指南

**版本**: v4.8.2  
**最後更新**: 2026-04-08  
**閱讀時間**: 10 分鐘

---

## 🎯 什麼是文件掃描？

**7 個核心文件掃描**是 v4.8.2 新增的功能，每週五 15:00 自動掃描 7 個核心文件，確保文件內容規範、無重複。

**解決的問題**：
- ❌ 文件亂記東西（內容不符合定義）
- ❌ 不同文件重複記錄相同內容
- ❌ 缺乏自動化清理機制

---

## 📋 掃描內容

### 檢查 1：文件內容是否符合定義

| 文件 | 應該包含 | 不應該包含 |
|------|---------|-----------|
| **SOUL.md** | 價值觀、邊界、原則 | 配置、規範、具體工作流程 |
| **USER.md** | 用戶信息、偏好 | 記憶、規範、配置 |
| **IDENTITY.md** | 名字、emoji、風格 | 價值觀、規範 |
| **AGENTS.md** | 行為規範、工作流程 | 配置值、個人偏好 |
| **TOOLS.md** | 本地配置、設備信息 | 規範、工作流程 |
| **MEMORY.md** | 長期記憶、經驗教訓 | 配置、規範、臨時記錄 |
| **HEARTBEAT.md** | 心跳檢查配置 | 流程圖、使用說明、對比表 |

**檢測關鍵詞**：
```bash
# SOUL.md 不應該包含
appId|appSecret|URL|端口|SSH|應該 | 禁止 | 規範

# AGENTS.md 不應該包含
appId|appSecret|攝像頭|SSH|TTS

# TOOLS.md 不應該包含
應該 | 不應該 | 必須 | 禁止 | 規範 | 流程

# MEMORY.md 不應該包含
appId|appSecret|URL|應該 | 禁止 | 規範

# HEARTBEAT.md 不應該包含
┌─|│|└─|→|↓  # 流程圖符號
```

---

### 檢查 2：不同文件之間的重複內容

**檢測方法**：
- 提取每個文件的關鍵段落
- 使用相似度比較
- 檢測重複率 > 80% 的內容

**常見重複**：
- ❌ 時間詞彙轉換規則（同時在 AGENTS.md 和 MEMORY.md）
- ❌ 安全紅線（同時在 AGENTS.md 和 SOUL.md）
- ❌ 飛書配置（同時在 TOOLS.md 和 AGENTS.md）
- ❌ 記憶系統說明（同時在多個文件）

**處理方式**：
1. 生成重複報告
2. 建議保留位置
3. 飛書推送確認

---

### 檢查 3：需要刪除/移除/遷移的內容

**檢測標準**：

| 類型 | 標準 | 操作 |
|------|------|------|
| **過期配置** | 配置值已變更 | 標記為待刪除 |
| **錯誤位置** | 內容在不正確的文件 | 建議遷移 |
| **重複內容** | 與其他文件重複 > 80% | 建議刪除冗餘 |
| **臨時記錄** | 包含"臨時"、"測試"等關鍵詞 | 建議清理 |

**確認流程**：
```
掃描腳本執行
    ↓
生成優化建議報告
    ↓
飛書推送確認消息
    ↓
用戶確認（回覆 y/n）
    ↓
執行操作（刪除/遷移）
    ↓
記錄到 LEARNINGS.md
```

## 🔧 使用方式

### 自動執行（推薦）

**執行頻率**：每週五 15:00

**配置方式**：
```json
// cron/jobs.json
{
  "name": "7 個核心文件掃描",
  "schedule": {
    "kind": "cron",
    "expr": "0 15 * * 5"
  },
  "payload": {
    "kind": "systemEvent",
    "text": "執行 7 個核心文件掃描"
  }
}
```

---

### 手動執行

```bash
# 執行掃描
~/.openclaw/workspace/.scripts/scan-core-files.sh

# 查看掃描報告
cat ~/.openclaw/workspace/memory/scan-report-$(date +%Y%m%d).md
```

## 🦞 飛書確認流程

### 確認消息格式

```
🔍 7 個核心文件掃描報告

**掃描時間**: 2026-04-08 15:00
**發現問題**: 1 個

**問題詳情**:
- ⚠️ '記憶系統' 出現在 2 個文檔中

**建議操作**:
1. 審查掃描報告
2. 確認需要執行的操作
3. 回覆 y/n 確認

**報告位置**: memory/scan-report-20260408.md
```

---

### 確認操作

**回覆格式**：
- `y` 或 `是` - 確認執行建議操作
- `n` 或 `否` - 取消操作
- `查看報告` - 查看完整報告

**執行結果**：
```
✅ 已執行確認的操作
- 刪除重複內容：1 處
- 遷移錯誤位置內容：0 處
- 記錄到 LEARNINGS.md

詳細信息：memory/scan-report-20260408.md
```

## 📚 常見問題

### Q1：掃描頻率是多少？

**A**: 每週五 15:00 自動執行，也可以手動執行。

### Q2：發現問題會自動處理嗎？

**A**: 不會。掃描報告會通過飛書推送，需要用戶確認後才執行操作。

### Q3：如何查看歷史掃描報告？

**A**: 掃描報告保存在 `memory/scan-report-YYYYMMDD.md`，可以按日期查看。

```bash
# 查看本月所有掃描報告
ls -lh ~/.openclaw/workspace/memory/scan-report-*.md
```

### Q4：掃描腳本在哪裡？

**A**: `~/.openclaw/workspace/.scripts/scan-core-files.sh`

### Q5：如何修改檢測規則？

**A**: 編輯 `scan-core-files.sh` 腳本中的關鍵詞檢測規則。

## 📖 示例場景

### 場景 1：發現 SOUL.md 包含配置值

**掃描結果**：
```
⚠️ SOUL.md 發現配置類內容（應該在 TOOLS.md）
```

**建議操作**：
```
建議遷移：
- 從 SOUL.md 刪除配置值
- 添加到 TOOLS.md
```

**確認流程**：
1. 收到飛書通知
2. 審查掃描報告
3. 回覆 `y` 確認
4. 自動執行遷移

---

### 場景 2：發現重複內容

**掃描結果**：
```
⚠️ '時間詞彙轉換' 出現在 2 個文檔中：AGENTS.md, MEMORY.md
```

**建議操作**：
```
建議保留：
- 保留在 AGENTS.md（行為規範）
- 從 MEMORY.md 刪除

理由：
- 時間詞彙轉換是行為規範，不是記憶
```

---

### 場景 3：發現臨時記錄

**掃描結果**：
```
⚠️ HEARTBEAT.md 發現臨時記錄，建議清理
```

**建議操作**：
```
建議刪除：
- 臨時測試內容
- 過期配置說明
```

## 🎯 最佳實踐

### 1. 定期審查掃描報告

- 每週五收到通知後立即審查
- 確認需要執行的操作
- 記錄到 LEARNINGS.md

### 2. 保持文件規範

- SOUL.md 只包含價值觀
- AGENTS.md 只包含行為規範
- TOOLS.md 只包含配置值
- MEMORY.md 只包含經驗教訓

### 3. 避免重複記錄

- 新增內容時先搜索是否已存在
- 使用文檔索引找到正確位置
- 遵循內容邊界規則
