## ✨ 新增功能

### 1️⃣ 7 個核心文件掃描腳本

**文件名**: `.scripts/scan-core-files.sh`

**掃描頻率**：每週五 15:00（Public Sharing 之前）

**掃描內容**：

#### 檢查 1：文件內容是否符合定義

| 文件 | 應該包含 | 不應該包含 |
|------|---------|-----------|
| **SOUL.md** | 價值觀、邊界、原則 | 配置、規範、具體工作流程 |
| **USER.md** | 用戶信息、偏好 | 記憶、規範、配置 |
| **IDENTITY.md** | 名字、emoji、風格 | 價值觀、規範 |
| **AGENTS.md** | 行為規範、工作流程 | 配置值、個人偏好 |
| **TOOLS.md** | 本地配置、設備信息 | 規範、工作流程 |
| **MEMORY.md** | 長期記憶、經驗教訓 | 配置、規範、臨時記錄 |
| **HEARTBEAT.md** | 心跳檢查配置 | 流程圖、使用說明、對比表 |

**檢查方式**：
```bash
# 關鍵詞檢測
SOUL.md 不應該包含：appId, appSecret, URL, 端口，應該，禁止
AGENTS.md 不應該包含：appId, appSecret, 攝像頭，SSH
TOOLS.md 不應該包含：應該，禁止，規範，流程
```

---

#### 檢查 2：不同文件之間的重複內容

**檢測方法**：
```bash
# 提取每個文件的關鍵段落
# 使用 diff 或相似度算法
# 檢測重複率 > 80% 的內容
```

**常見重複**：
- ❌ 時間詞彙轉換規則（同時在 AGENTS.md 和 MEMORY.md）
- ❌ 安全紅線（同時在 AGENTS.md 和 SOUL.md）
- ❌ 飛書配置（同時在 TOOLS.md 和 AGENTS.md）
- ❌ 記憶系統說明（同時在多個文件）

**處理方式**：
- 生成重複報告
- 建議保留位置
- 飛書推送確認

---

#### 檢查 3：需要刪除/移除/遷移的內容

**檢測標準**：

| 類型 | 標準 | 操作 |
|------|------|------|
| **過期配置** | 配置值已變更 | 標記為待刪除 |
| **錯誤位置** | 內容在不正確的文件 | 建議遷移 |
| **重複內容** | 與其他文件重複 > 80% | 建議刪除冗餘 |
| **臨時記錄** | 包含"臨時"、"測試"等關鍵詞 | 建議清理 |

**確認流程**：
```
掃描腳本執行
    ↓
生成優化建議報告
    ↓
飛書推送確認消息
    ↓
用戶確認（回覆 y/n）
    ↓
執行操作（刪除/遷移）
    ↓
記錄到 LEARNINGS.md
```

### 2️⃣ 定時任務優化

#### 現有任務分析

| 任務 | 頻率 | 問題 | 優化方案 |
|------|------|------|---------|
| **記憶復述** | 每天 08:30 | ✅ 已自動化 | 保持現狀 |
| **記憶巩固** | 每週一 05:00 | ✅ 已自動化 | 保持現狀 |
| **記憶檢索** | 每週五 10:00 | ✅ 已自動化 | 保持現狀 |
| **情緒趨勢** | 每週五 11:00 | ⚠️ 報告沒人看 | 改為按需觸發 |
| **自我反思** | 每週五 17:00 | ⚠️ 報告沒人看 | 併入待處理事項日報 |
| **Public Sharing** | 每週五 16:00 | ⚠️ 未啟用 | 暫緩 |
| **記憶清潔** | 每月 1 日 06:00 | ⚠️ 閾值不合理 | 調整為記錄數閾值 |
| **指南更新** | 每月 1 日 07:00 | ⚠️ 報告沒人看 | 併入心跳檢查 |
| **待處理事項** | 每天 09:25 | ✅ 已推送 | 保持現狀 |
| **Smart Auto-Update** | 每天 07:00 | ✅ 已推送 | 保持現狀 |

---

#### 優化方案

**方案 1：合併同類任務**

```
每週五任務優化：
- 10:00 記憶檢索優化 ✅ 保持
- 11:00 情緒趨勢分析 ❌ 改為按需
- 15:00 7 個核心文件掃描 ✅ 新增
- 16:00 Public Sharing ❌ 暫緩
- 17:00 自我反思 ❌ 併入待處理事項日報

優化後：
- 10:00 記憶檢索優化
- 15:00 7 個核心文件掃描
- 17:00 每週總結（合併自我反思 + 情緒趨勢）
```

---

**方案 2：調整執行時間**

```
當前問題：
- 定時任務集中在早上（05:00-10:00）
- 用戶起床時收到多條推送

優化後：
- 05:00 記憶巩固（保持，用戶起床前完成）
- 08:30 記憶復述（保持，用戶上班前完成）
- 09:25 待處理事項日報（保持）
- 15:00 7 個核心文件掃描（新增，下午工作時間）
- 17:00 每週總結（週五，下班前總結）
```

---

**方案 3：添加條件觸發**

```
當前問題：
- 定時任務無論有無內容都執行
- 浪費資源

優化方案：
- 記憶復述：只有 HOT 層有記錄時執行
- 記憶巩固：只有 WARM 層有待處理記錄時執行
- 7 個核心文件掃描：只有文件變更時執行
- 情緒趨勢：檢測到消極情緒時觸發

實現方式：
```bash
# 檢查是否有待處理內容
if [ $(find memory -name "*.trigger-*.md" | wc -l) -gt 0 ]; then
    執行處理
else
    跳過執行
fi
```

---

**方案 4：添加心跳檢查項目**

```
當前心跳檢查（每 30 分鐘）：
- ✅ 記憶系統自動處理檢查

新增檢查：
- ✅ 7 個核心文件變更檢查
- ✅ 定時任務執行狀態檢查
- ✅ 待確認事項檢查

實現方式：
```bash

check_core_files_changes() {
    # 檢查 7 個核心文件是否有未確認的變更
    # 如有，推送飛書提醒
}

check_cron_status() {
    # 檢查定時任務是否正常執行
    # 如有失敗，推送飛書警告
}
```
